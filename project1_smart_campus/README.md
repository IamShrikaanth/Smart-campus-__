# Mini Project 1 — Smart Campus Resource Demand Predictor

This project predicts whether a college facility (Library, Computer Lab, Canteen,
Seminar Hall, Classroom, Wifi Zone) will face **Low, Medium, or High** demand based
on the day, time, department, and expected number of students.

## Folder Contents

| File | Purpose |
|---|---|
| `data_generator.py` | Creates the dataset `facility_usage.csv` |
| `facility_usage.csv` | The dataset used by the project (650 records) |
| `database_setup.sql` | SQL script that creates and fills the database tables |
| `sql_runner.py` | Runs the SQL script using SQLite and prints query results |
| `main.py` | The full project — cleaning, feature engineering, visualization, ML models, clustering, final prediction |
| `requirements.txt` | Python libraries needed |
| `*.png` | Graphs generated by the project |
| `campus.db` | SQLite database created after running `sql_runner.py` |

## What Was Actually Done In This Project

- Created a dataset with 650 rows covering 6 facilities, 6 days, 9 time slots and 6 departments.
- Built 4 SQL tables (`students`, `facility_master`, `facility_usage`, `daily_usage`) and wrote
  SQL queries using `WHERE`, `GROUP BY`, `ORDER BY`, aggregate functions, `JOIN` and a subquery.
- Wrote 5 Python classes: `Student`, `Facility`, `UsageRecord`, `DemandPredictor`, `ReportGenerator`.
- Cleaned the data with Pandas (removed duplicates/missing values) and engineered new columns:
  `Occupancy_Percentage`, `Usage_Rate`, `Peak_Hour`, `Previous_Day_Usage`, `Average_Weekly_Usage`.
- Used NumPy to calculate mean, max, min, standard deviation and to normalize the student-count column.
- Created 7 graphs with Matplotlib and Seaborn: daily usage, weekly trend, peak-hour analysis,
  facility comparison, correlation heatmap, demand distribution, usage vs occupancy scatter plot,
  and a department-vs-facility heatmap.
- Trained and compared 4 ML models (KNN, Naive Bayes, Decision Tree, Random Forest) to predict
  `Demand_Level`, and automatically picked the best one based on accuracy.
- Applied K-Means clustering (unsupervised) on `Students`, `Previous_Usage`, and `Occupancy_Percentage`
  to group facilities into Low-usage, Regular-usage, and Peak-demand clusters — without using the
  demand label at all.
- Built a final mini "application" at the bottom of `main.py` that takes a facility, day, time,
  department, expected students and previous usage, and prints the predicted demand plus a
  recommendation.

## Code Explanation

### `data_generator.py`
This script builds the dataset from scratch using Python's `random` module. For every row it
picks a random facility, day, time slot and department, then decides a student count — during
peak time slots (10 AM, 1 PM, 2 PM) the count is pushed higher to simulate rush hours. It works
out the occupancy percentage (`students / capacity * 100`) and uses simple thresholds
(70% → High, 40% → Medium, below → Low) to label the demand. A small amount of random noise
is added so the labels are not perfectly clean, which makes the ML part more realistic.

### `database_setup.sql`
Creates four tables that mirror the real project structure (`students`, `facility_master`,
`facility_usage`, `daily_usage`), inserts sample rows (including the exact example rows from
the project brief — Library/Monday/10 AM etc.), and contains SQL queries demonstrating
`WHERE`, `GROUP BY`, `ORDER BY`, aggregate functions (`AVG`, `COUNT`), `JOIN`, and a subquery
(facilities with capacity above the average capacity).

### `sql_runner.py`
A small script that opens a SQLite database file (`campus.db`), runs the entire SQL script on
it, then re-runs a few of the queries individually using `cur.execute()` and prints the results
row by row, so you can see the SQL working live instead of only reading the `.sql` file.

### `main.py`
This is the heart of the project.

- **Classes**
  - `Student` — holds a student's id, name and department.
  - `Facility` — holds a facility's name, capacity, location and type, with a `show_info()` method.
  - `UsageRecord` — represents one usage record and can calculate its own `occupancy_percentage()`.
  - `DemandPredictor` — encodes the categorical columns, trains all 4 ML models, keeps track of
    which one is most accurate, and has a `predict_demand()` method used by the final application.
  - `ReportGenerator` — prints a summary of the dataset and model results, and turns a predicted
    demand level into a plain-English recommendation.

- **Functions**
  - `clean_and_engineer(df)` — removes duplicate/missing rows and creates the new feature columns
    mentioned in the project brief.
  - `numpy_stats(df)` — uses NumPy to compute mean/max/min/standard deviation of student counts
    and adds a normalized column.
  - `make_visualizations(df)` — builds and saves all 7 required graphs as PNG files.
  - `run_kmeans(df)` — runs K-Means with 3 clusters on usage-related columns and labels each
    cluster as Low/Regular/Peak based on their average occupancy.
  - `main()` — loads the CSV, calls all the steps above in order, trains the models, prints the
    report, and finally runs the "Computer Lab / Monday / 2 PM / 210 students" example exactly
    like the sample shown in the project description.

## How To Run This Project

1. Make sure Python 3.8+ is installed.
2. Open a terminal inside the `project1_smart_campus` folder.
3. Install the required libraries:
   ```
   pip install -r requirements.txt
   ```
4. (Optional — the CSV is already included) Regenerate the dataset:
   ```
   python data_generator.py
   ```
5. Run the SQL part to see the database in action:
   ```
   python sql_runner.py
   ```
6. Run the full project (cleaning, visualization, ML, clustering, final prediction):
   ```
   python main.py
   ```
7. Check the folder for the generated `.png` graph files and the `campus.db` database file.

The final part of the terminal output will show something like:
```
Facility: Computer Lab
Day: Monday | Time: 2 PM
Expected Students: 210
Previous Usage: 190
Predicted Demand: HIGH
Recommendation: Additional resources may be required...
```
